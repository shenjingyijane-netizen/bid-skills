# 第一阶段字段规范

## 通用原则

- 模板字段保持行业中立，所有具体名称和要求来自本次招标文件。
- 未说明写“未说明”，无法判断写“待人工确认”，不得猜测。
- 所有关键结论保留可复核的原文位置：有稳定页码时写“标题/条款 + 页码”；没有稳定页码时写“标题/条款/表名 + 可搜索原文短句”。

## Sheet1：项目介绍

### 企业级投标准入审查

判断标准是“企业主体本身能不能投”，而不是“中标后准备怎样履约”。

先排除报名和文件获取阶段。凡要求仅用于报名、登记、购买、领购、发售、领取、下载或获取招标/采购文件，即使其中提到营业执照、授权书、身份证明、信用或其他资质词，也不进入本表。可用于定位的常见表述包括“报名文件、报名材料、获取招标文件、招标文件获取、采购文件获取、获取方式、获取所需材料、文件领取、文件下载、文件发售、文件售价”等。

判断不能只匹配关键词，还要查看条款标题、上下文和不符合后果。后果仅为不能报名、不能取得文件或报名无效时直接排除；只有该条件在正式投标资格、资格审查、无效投标或否决条款中再次明确出现时才纳入。阶段仍不清楚时不得作为资格停止项，在`项目内容与关键要求`中标为待人工确认。

纳入：企业主体、证照许可、经营范围、有效期、企业信用、企业规模、主体名单或备案、联合体及关联关系等。

排除：人员年龄和个人材料、设备或产品参数、保险配置、服务流程、实施资源、方案承诺、评分加分条件及中标后事项。边界不清且可能影响资格时，在`项目内容与关键要求`中标为待人工确认，不直接判定。

字段：

- **具体核验问题**：包含原文的准确名称、范围、期限、数值或记录类型；一行一个事实；是始终代表通过。
- 复合条件拆成多行，不得生成“是否符合全部资格要求”“现有资质是否覆盖要求”等模糊问题。
- 中立拆分示例：原文要求“持有 A 证书和 B 备案，且均在有效期内”时，分别生成“是否持有 A 证书”“A 证书是否在有效期内”“是否完成 B 备案”“B 备案是否在有效期内”；原文要求“未列入 X 名单且近三年无 Y 记录”时，拆成两行。实际输出必须用本次文件中的准确名称替换占位符。
- **核对材料/查询入口**：用户只需查看的单一材料、栏目、附件或页面；原文没有网址时不得编造。
- **用户选择**：真实 Excel 下拉框，仅有是、否。
- **自动状态**：公式生成通过、不通过、待确认。
- **不符合后果**：只写原文明示后果；未明确写“未明确”。
- **原文位置**：按通用原则提供稳定页码或可搜索定位信息。
- **备注**：只记录识别限制或补充说明。

空白模板不得预设任何行业、证照、名单或信用记录名称；具体内容只能来自本次文件。

可选的整行条件颜色：是为浅绿色，否为浅红色，已生成问题但未选为黄色。条件格式只允许改变背景色，不得改变字体颜色；平台无法可靠实现时可不着色，但必须保留清晰可见的`是/否`和`通过/不通过`文字。

### 项目30秒概览

- **项目名称/编号**：正式名称和识别编号。
- **项目一句话定义**：采购主体 + 实际采购内容 + 服务/交付对象 + 核心用途或目标；未说明时明确标注，不复述标题。
- **采购人/代理机构/采购方式/中标数量**：按原文填写。
- **投标截止时间/开标地点**：分别填写。
- **原文位置**：主要出处。

价格计算基准只能解释价格如何计算，不能据此推断项目用途、服务频次或场景。

### 项目内容与关键要求

每个相对独立的项目组成占一行：

- 项目组成。
- 采购范围或关键要求。
- 服务或交付对象。
- 时间。
- 地点。
- 数量或规模。
- 标准或成果。
- 验收方式。
- 原文位置。

每一行应能独立说明具体内容，避免“相关服务、按要求执行”等空泛表达。整体应覆盖谁采购、采购什么、为谁服务或向谁交付、怎样实施、何时何地、数量规模、标准成果和验收方式；缺失字段写“未说明”。

不再另建履约安排表。详细人员、设备、服务流程和方案响应留给第二阶段。

### 合同核对

合同比对动作和展示内容分开：文件存在合同模板、合同主要条款或拟签合同文本时，内部必须完成逐项比对；Excel只显示核对摘要，并在发现异常时展开明细。

逐项比较合同与项目需求对同一事项的项目名称、范围、对象、期限频次、时间地点、数量规模、标准资源、价格税费、结算付款、验收、不合格处理、违约风险、变更终止等口径。每个内部比对项必须保存事项名称、项目需求原文、合同原文、双方位置和核对结果，不能只写总结。

核对结果固定为：`一致`、`明确冲突`、`疑似冲突`、`合同未覆盖`、`项目需求未覆盖`或`待确认`。

- 文件未提供合同：显示一行“未提供合同模板，不适用”，不展开明细。
- 有合同且全部一致：显示一行“合同核对已完成，未发现需要人工确认的差异”，不展开明细。
- 有合同且存在非`一致`项：显示核对摘要，并只展开这些异常项；一致项保留在内部数据中，不占用 Excel 行。
- 异常明细必须并列双方原文、核对结果、待确认问题、可能影响和双方位置；不得自行决定合同或需求必然优先。

全文检索“合同仅为模板/参考、具体以实际签订为准、以采购需求/服务需求/投标响应/服务方案为准、如有冲突以某文件为准、合同可调整或另行约定”等适用说明。找到时在核对摘要中准确显示原文和位置；没有时写“未说明”，不得虚构。

异常项的人工确认状态固定为：`待确认`、`已确认有冲突`、`已确认无冲突`。明确冲突使用浅红色提醒，其他未确认差异使用黄色；条件格式不得改变字体颜色。

### 报价限制提示

每个独立限制占一行：

- **适用范围**：项目、包件、标段、规格或其他原文范围。
- **限制类型**：使用原文名称，不预设只有最高总价。
- **文件明确要求**：限制数值、条件或计算边界。
- **含税要求**：含税、不含税或未说明。
- **原始报价载体**：招标人提供的报价表、清单、系统页面或其他载体及位置。
- **不符合后果**：只写原文明示后果。
- **原文位置**：章节、附件或页码。

不得重建报价明细或设计新的计价结构。

评分标准、得分条件和响应材料不在第一阶段展示，统一留给后续“标书撰写”阶段。
